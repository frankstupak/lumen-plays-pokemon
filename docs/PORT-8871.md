# Port 8871 has one owner

`pokemon.lumennode.uk` is a single TCP port, and two things want it: the live
agent's stream server (`src/stream.ts`, bound by `src/live_agent.ts`) and the
idle cover that keeps the site off a 502 while the agent is down. Only one of
them is the owner.

**The live agent owns :8871. The cover borrows it and gives it back.**

## What went wrong when that was not true (wq#1661)

`LPP_BEHAVIORAL_ANALYSIS.md` M1: on 2026-08-27 between 04:24 and 19:49Z the live
service restarted **355 times at a 231s period**. Every start logged
`[stream] port 8871 in use retry 1..12/12` and then `FATAL EADDRINUSE, exit 1`.
The cover was `python3 -m http.server` under `Restart=always`: once it had the
port it had no reason to let go, and live's `ExecStartPre=-… stop` was a
best-effort race against the `OnFailure=` job that had just raised it. The bind
retry added in af77d9d bought 110s and then crashed anyway.

wq#1021 made preemption one-directional and gave the cover a state guard, which
ended the outage. What it did not end was the handoff race. On 2026-09-10 at
06:38:08 and 06:38:10, two restarts each raised the cover from live's own
`ExecStopPost`, and each was refused a moment later and logged as a unit
failure. The hook was asking an unanswerable question: it polled `ActiveState`
for 1.5s waiting to see live come back, but it runs *inside* the stop job, so
the queued start cannot begin until it returns and the state reads
`deactivating` for the entire window. Every restart looked like a permanent stop.

## The contract

| Event | Who holds :8871 | Mechanism |
|---|---|---|
| live running | live | it binds; the cover refuses to start |
| live crashes, will retry | nobody, for `RestartSec` | `$SERVICE_RESULT != success` → hook does nothing; cover refuses (`activating`) |
| live restarts | live | a start/restart job is queued → hook does nothing |
| live stopped for good | cover | hook raises the cover |
| live durably failed | cover | `OnFailure=lumen-kiosk-idle.service` |
| cover up, live starts | live | `ExecStartPre` stops the cover; the cover also yields on its own |

Three rules enforce it, each independently sufficient to keep the port:

1. **Settle** — `tools/lpp-cover-serve` refuses to bind while live is `active`,
   `activating`, `reloading` or `deactivating`, and keeps refusing for
   `--settle-sec` (5s). A restart hands the port back in milliseconds, so a
   cover raised during one never binds. Refusal is `exit 0`, not a failure.
2. **Claim** — one bind. A port held by a foreign process is `exit 3`, and
   `RestartPreventExitStatus=3` stops that from becoming a retry storm.
3. **Yield** — while serving, the cover watches live and shuts down the moment
   it is `activating` or `active`. This is the rule that makes the invariant
   hold no matter how the units race: the cover can lose a race for a second,
   but it cannot keep the port. Live's own retry (1s, 1.5s, 2.25s, …) then
   succeeds on its first or second attempt.

`tools/lpp-cover-maybe-up` (live's `ExecStopPost`) reads the systemd job queue
instead of polling `ActiveState`: a pending job for live that is not a `stop`
means live is coming back, so the cover stays down.

## Files

- `deploy/lumen-pokemon-live.service` — the owner. One-directional preempt; a
  bidirectional `Conflicts=` pair was tried and rejected on 2026-08-27 because it
  cancelled live's own auto-restart on a transient crash. The old
  `deploy/lumen-lpp-brb.service` had that shape and was deleted with this change.
- `deploy/lumen-kiosk-idle.service` — the cover. Never `systemctl enable` it.
- `tools/lpp-cover-serve` — settle, claim, yield.
- `tools/lpp-cover-maybe-up` — raise the cover on a stop, never on a restart.
- `tools/test_1661_port_8871.py` — the proof, including a forced 12-round crash
  loop. Run it with `python3 tools/test_1661_port_8871.py`; it fakes systemd but
  uses real sockets and the real scripts, and needs no root.

## Installing a change to any of this (needs root)

> **LPP is decommissioned (wq#2073). Installing these files does not revive it,
> and it must not.** `lumen-pokemon-live.service` is masked *and* carries an
> `AssertPathExists=!` on `DECOMMISSIONED.md`, and `src/live_agent.ts` refuses
> to boot while that file exists. Run steps 1-2 below to ship a change to the
> port contract; **do not `systemctl unmask`** and skip step 3. Unmasking is a
> revival, and revival needs a free local brain plus Frank — read
> `DECOMMISSIONED.md` first. wq#1990 unmasked here on 2026-09-18 in good faith
> because this section said nothing about it; that cost 19h of brain calls and
> Frank's MCP sessions (`reports/2073_lpp_resurrection_rca.md`).

```
sudo cp deploy/lumen-pokemon-live.service deploy/lumen-kiosk-idle.service /etc/systemd/system/
sudo systemctl daemon-reload
/home/lumen/bin/lpp-restart --ticket wq#<n>     # the only sanctioned restart path
```

`cp` rather than `install` in step 1 is load-bearing while the unit is masked.
`cp` opens the destination and truncates it, so it writes *through* the
`/dev/null` mask symlink and the symlink survives; `install -m 0644` unlinks the
destination first and replaces the mask with a real unit file. The 2026-09-18
resurrection did both — an explicit `systemctl unmask` and then `install` — so
neither tool is the villain, but `cp` is the one that cannot unmask by accident.

The previous scripts at `/home/lumen/bin/lpp-cover-maybe-up` and
`/home/lumen/bin/lpp-idle-guard` are superseded by `tools/`: the units above no
longer reference them, and `lpp-idle-guard`'s job (refuse while live owns the
port) is rule 1 inside `lpp-cover-serve`. Delete them once the units are in
place.
